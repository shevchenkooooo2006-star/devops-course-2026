## 📚 Теоретическая справка

### 1. Что такое DevOps?

**DevOps** (от англ. *Development* и *Operations*) — это культура и набор практик, направленных на автоматизацию и унификацию процессов между командами разработки (Dev) и эксплуатации (Ops). Главная цель — выпускать качественный продукт быстрее, чаще и надёжнее.

**Ключевая проблема, которую решает DevOps — «Стена недопонимания» (Wall of Confusion):**
- **Разработчики** хотят быстро вносить изменения, выпускать новые фичи.
- **Системные администраторы** хотят стабильности и предсказуемости, чтобы система не падала.
- **Итог:** релизы редкие, болезненные, а фраза *«на моей машине работает»* становится мемом.

DevOps ломает эту стену через автоматизацию, общую ответственность и единые инструменты.

### 3. Метрики DORA

Успешность DevOps-команд измеряют по 4 ключевым метрикам (исследование DORA):
1. **Deployment Frequency** — частота выкладок на продакшен.
2. **Lead Time for Changes** — время от коммита до попадания в продакшен.
3. **Change Failure Rate** — процент неудачных релизов (требующих хотфиксов или откатов).
4. **Time to Restore Service** — время восстановления после инцидента.

### 4. DevOps на рынке труда

DevOps-инженер — одна из самых востребованных и высокооплачиваемых IT-профессий.

## 💻 Практическая часть

### Задание 1. Установка и настройка Git

**Шаг 1.1.** Убедитесь, что Git установлен. Откройте терминал (в Windows — Git Bash) и выполните:

```bash
git --version
```
> ⚠️ Если Git не установлен, скачайте его с официального сайта: [git-scm.com/downloads](https://git-scm.com/downloads)

**Шаг 1.2.** Настройте свой профиль. Эти данные будут «пришиты» к каждому вашему коммиту и видны всем в истории:

```bash
git config --global user.name "Иван Иванов"
git config --global user.email "ivanov@university.edu"
```

**Шаг 1.3.** Проверьте, что настройки сохранились:

```bash
git config --list
```

**Шаг 1.4.** (Рекомендуется) Установите VS Code как редактор по умолчанию для сообщений коммитов:

```bash
git config --global core.editor "code --wait"
```

📖 **Документация:** [Pro Git Book — Первоначальная настройка (на русском)](https://git-scm.com/book/ru/v2/Введение-Первоначальная-настройка-Git)

### Задание 2. Регистрация на GitHub и настройка SSH

Работать через HTTPS (по логину и паролю/токену) менее удобно для постоянной работы. Настроим безопасную SSH-аутентификацию.

**Шаг 2.1.** Зарегистрируйтесь на [github.com](https://github.com/) (если ещё нет аккаунта) или на gitverse. Придумайте профессиональный никнейм (без лишних цифр и никнеймов из игр).

**Шаг 2.2.** Сгенерируйте SSH-ключ (алгоритм ed25519 — современный и безопасный):

```bash
ssh-keygen -t ed25519 -C "ваш_email@university.edu"
```
*На все вопросы нажимайте `Enter` (используйте путь по умолчанию, парольную фразу для ключа можно оставить пустой для упрощения учебной работы).*

**Шаг 2.3.** Скопируйте публичный ключ в буфер обмена:

```bash
# Linux / macOS
cat ~/.ssh/id_ed25519.pub | xclip -selection clipboard
# или просто откройте файл ~/.ssh/id_ed25519.pub и скопируйте текст вручную

# Windows (Git Bash)
cat ~/.ssh/id_ed25519.pub
```

**Шаг 2.4.** Добавьте ключ в GitHub:
1. Откройте `Settings` (справа сверху) → `SSH and GPG keys` (в левом меню) → `New SSH key`.
2. Вставьте скопированный ключ в поле "Key", дайте ему понятное название (например, `University Laptop`).

**Шаг 2.5.** Проверьте подключение:

```bash
ssh -T git@github.com
```

Ожидаемый ответ:
> *Hi username! You've successfully authenticated, but GitHub does not provide shell access.*

📖 **Документация:** [GitHub Docs — Подключение к GitHub по SSH (на русском)](https://docs.github.com/ru/authentication/connecting-to-github-with-ssh)

### Задание 3. Первый репозиторий

**Шаг 3.1.** На GitHub создайте новый публичный репозиторий:
- Название: `devops-course-2026`
- Поставьте галочку **Add a README file**
- Нажмите **Create repository**

**Шаг 3.2.** Клонируйте репозиторий на локальную машину (используйте **SSH**-адрес, который выдает GitHub):

```bash
git clone git@github.com:ваш_username/devops-course-2026.git
cd devops-course-2026
```

**Шаг 3.3.** Создайте файл `about_me.md` (можно через терминал `touch about_me.md` или в редакторе кода) и заполните его:

```markdown
# Обо мне

- ФИО: Иванов Иван
- Группа: ЭФБО
- Технологии, которые хочу освоить в этом курсе:
  1. Docker
  2. CI/CD (GitHub Actions)
  3. Linux (Bash)
```

**Шаг 3.4.** Посмотрите статус репозитория:

```bash
git status
```
*Обратите внимание: файл подсвечен красным — он пока не отслеживается Git (Untracked).*

**Шаг 3.5.** Добавьте файл в индекс (staging area) и создайте коммит:

```bash
git add about_me.md
git commit -m "Add about_me.md with student info"
```

**Шаг 3.6.** Отправьте изменения на удалённый сервер (GitHub):

```bash
git push origin main
```

**Шаг 3.7.** Обновите страницу репозитория на GitHub и убедитесь, что файл там появился.
